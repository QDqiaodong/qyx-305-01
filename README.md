# qyx-305 研学路线出行风险多维度自动筛查预警系统

## 项目简介
研学路线出行风险多维度自动筛查预警系统，包含 Spring Boot 后端、Vue/Vite 前端、MySQL 和 Redis。

## 前端访问地址
- 默认地址：http://localhost:8205
- 127.0.0.1：http://127.0.0.1:8205

## 端口
- 前端：8205
- 后端 API：8305
- MySQL：3405
- Redis：6505

sh start.sh

## 发车放行：两本账必须同时成立
系统在“风险筛查 / 报告”之外，补齐了 **随队医护排班** 与 **发车放行** 两块，发车当天同时核两本账：

1. **筛查时效账**：该计划最新一次筛查仍对得上当前的出行日期、参与人数、年龄段、途经点（以行程指纹比对）。上述任一项被改动，旧筛查、旧报告立即失效，已发出的放行单落到「已作废（行程变了）」，必须重新筛查。
2. **医护覆盖账**：出行日排班满足覆盖——最小年龄 ≤ 8 岁至少一名儿科资质；高风险双人值班；同一名医护同一天不能挂两条计划。医护被抽走导致覆盖断裂，已放行单掉到「筛查失效待重评」，不再显示可出门。

放行单四档：`待齐件 / 已放行 / 已作废 / 筛查失效待重评`。
安全岗硬规则：**高风险一律不得出车**；知情备注只允许写在中风险单上，写了也不能把高风险改成可出门。放行条件不满足时提交会明确失败并逐条说明原因，第二次提交同样被拒，不会再悄悄出绿单。

## 规则变更与发车时刻：两本账始终对齐
- **规则版本**：风险规则每被改一次（新增/编辑/删除/开关），全库规则版本 +1。筛查台账记录筛查当时的规则版本；版本对不上即“规则改了还没重筛”。
- **未记下发车时刻的计划**：报告页与发车放行看板读同一份最新筛查。规则一改，未发车的出门条立即作废并停在「筛查失效待重评」，报告页同步不得把旧结论当可出门；两人同时改同一条规则，未发车计划只能一起落到待重筛。按新规则重筛、两本账齐后才可重新放行。
- **已记下发车时刻的单据**：在发车放行看板「确认发车」后单据封存——之后的规则调整、重筛、排班变动都不再改写这张纸，报告保持出门当时那一版；已发车的计划不能再重筛、作废或重复发车。

- 随队医护排班：侧边栏「随队医护排班」，按计划出行日挂人并实时给出覆盖结论。
- 发车放行看板：侧边栏「发车放行」，并排展示两本账、四档单据与放行/重筛/作废操作。
- 回程点名：侧边栏「回程点名」，回校后按发车时带出去的人一个个勾回收口。

## 回程点名：发车带出去谁，回校就得点回谁
研学车记下发车时刻后，回校必须在「回程点名」页把这趟点回来：

1. **发车前录名册**：还没发车时可在回程点名页增删这趟要带出去的人；一登记发车时刻名册即锁定。
2. **回校逐个勾回**：还没收口的车次，必须按发车时带出去的人一个个勾「已回」，勾选实时落库——关掉回程页再打开，勾过的还在，可以接着点。
3. **缺人先写说明**：有人没上车回校，必须先为每个缺员写下缺人说明（去向/原因），这趟才收得了口；空名册（只改口号、车上没人点名）收不了口，值班室仍当全员还没回来。
4. **收口即冻住**：收口后这趟的点名结果冻住——不能再往车上塞人、不能改勾选、也不能把缺人说明改没。调度希望晚到的孩子补进这趟，安全岗驳回：**收口之后人数冻住，晚到的只能另开一趟**；本趟名册在发车时刻登记时同样锁定，晚到的补不进来。
